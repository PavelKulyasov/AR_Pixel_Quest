# Готовность платформы и решения для обсуждения

## Вывод

Из текущего репозитория выделена рабочая основа для однопользовательских AR-квестов. Есть первый потребитель — Pixel Quest. Этого достаточно, чтобы разработчик начал похожую игру, переиспользуя AR, UI, состояние и звук. Для сборки произвольных игр из независимых модулей необходима следующая работа.

Согласовано с владельцем: сначала одиночные AR-квесты по ссылке на Android и iPhone. Мультиплеер, аккаунты и сервер не входят в первую версию.

## Что есть и чего не хватает

| Область | Уже есть в коде | Пробел / предлагаемое дополнение |
| --- | --- | --- |
| Запуск | Общий runtime, AR-регистрация, выбор игры при сборке | Проверка конфигурации игры, понятные ошибки и отмена частичной инициализации |
| Состояние | Хранилище в памяти, статусы маркеров | Отдельные игровые состояния, подписки, проверка переходов; сейчас первый маркер доступен автоматически |
| События | FIFO event bus, конверт сеанса/шага/попытки, очистка и изоляция аналитики | Добавлять типы входа вместе со следующими механиками |
| Сохранения | Нет; обновление страницы начинает заново | Локальное сохранение по gameId/episodeId/version, восстановление, сброс и миграция формата |
| AR | 8th Wall/A-Frame, маркеры, объекты и восстановление привязки | Диагностика качества трекинга, единая политика потери/восстановления; камера и внешние скрипты пока описаны сценой игры |
| Карта объектов | Пока отдельные привязки | IDEA-001: единая карта и коррекция по нескольким неподвижным маркерам; сначала физический прототип |
| UI | Общие панели, кнопки, сообщения, текст при ошибке речи | Темы, локализация и отделение браузерной речи от DOM; сейчас роли и служебный язык фиксированы |
| Диалоги | Текстовый формат view и контроллер первого эпизода | Граф диалогов, условия, персонажи и отдельный модуль воспроизведения; сейчас переходы написаны на JS |
| Задания | Текущая цель на экране и условия в контроллере | Общий модуль целей, условий, наград и журнал заданий |
| Инвентарь | Нет | Добавлять только если выбранной игре нужны предметы, получение, расход и комбинации |
| Звук | Отдельный синтезатор сигналов, браузерная речь | Аудиофайлы, фоновая музыка, раздельная громкость и смешивание — по требованиям игр |
| Аналитика | События, время, защита от дублей, sink | Идентификаторы игры/сеанса, список метрик; внешний сбор — только при необходимости |
| Модули | Реестр механик api_version=1, проверка возможностей, lifecycle, AR-01 SCAN, AR-02 DISCOVER, AR-03 TOUCH, AR-05 COLLECT, AR-06 CHOOSE и AR-07 SEQUENCE; фабрики audio/analytics | Итоговая приёмка шести MVP-механик; удалённой установки плагинов нет |
| Ресурсы | Файлы отдельной игры, общая сборка, сохранены лицензии | Каталог ресурсов с размерами/прогрессом загрузки, обработка ошибок и бюджет памяти |
| Несколько эпизодов | episode-01 и отдельный маршрут ar-initiation с шестью MVP-упражнениями | Общий прогресс, переходы и условия открытия |
| Проверки | Тесты логики, UI/звука, A-Frame с синтетическими событиями | Вторая полноценная игра и физические проверки Android/iPhone, камера, звук, возврат из фона |
| Публикация | Одна игра в dist/, существующий GitHub Pages | Согласовать адрес каждой игры, независимые сборки/релизы; общего каталога игр пока нет |

## Что делать дальше

1. Сделать маленькую вторую игру с другим сценарием и маркерами. Цель: подтвердить, что platform/ не требует копирования или добавления сюжетных исключений. Сейчас есть проверка runtime с другим контроллером, но это не вторая игра.
2. Развить согласованную библиотеку механик. Event bus, контракт, валидация и первый SCAN уже реализованы; DISCOVER и TOUCH также реализованы; COLLECT также реализован; CHOOSE также реализован; SEQUENCE также реализован; дальше итоговая приёмка MVP на устройствах.
3. Добавить локальные сохранения. Критерий: перезагрузка восстанавливает допустимый шаг; повреждённые/старые данные обрабатываются; новая игра не читает чужое сохранение. Сюжетный прогресс и AR-координаты хранить раздельно: координаты одной сессии трекинга нельзя просто восстановить в другой.
4. Выделить диалоги и задания по механикам второй игры. Инвентарь добавлять только при реальном сценарии его использования.
5. Отдельно прототипировать карту маркеров на месте проведения. Критерий: пройти согласованный маршрут, вернуться, восстановить карту по опорному маркеру; измерить погрешность. Общая карта пока не реализована этим переносом.
6. Выполнить проверку на целевых телефонах и подготовить независимую публикацию игр. Редактор без программирования можно рассматривать после стабилизации формата контента.

Общий план выше реализован частично: этапы SCAN, DISCOVER, TOUCH, COLLECT, CHOOSE и SEQUENCE завершены в коде; остальные задачи остаются впереди. Выделение папок не делает платформу автоматически готовой к любой игре.

## Что нужно от владельца

Программировать и переносить файлы вручную не требуется. Нужны продуктовые решения и проверка реальной среды:

- Короткий сценарий второй игры: цель, 2–3 взаимодействия, условие завершения, какие механики отличаются от Pixel Quest.
- Ближайший приоритет согласован: шесть MVP-механик по очереди. От владельца нужна физическая проверка каждого упражнения; карта остаётся отдельной задачей.
- Решить, должен ли игрок продолжать после закрытия вкладки, как сбрасывать прогресс и где проходит граница эпизодов.
- Для карты: план площадки, измеренные расстояния и размеры неподвижных маркеров, разрешённые места их размещения и допустимая погрешность.
- Предоставить материалы игры и права на них: изображения маркеров, модели, тексты и аудио. Для прототипа можно использовать временные ресурсы.
- Проверить итог на Samsung Android и доступном iPhone; указать браузер, модель, условия освещения и результат прохождения.
- Перед публикацией согласовать адрес/хостинг каждой игры. Действующий процесс публикации пока настроен на Pixel Quest.

Я могу самостоятельно реализовать структуру, контракты, новые модули, тесты, инструкции и подготовку сборок. Выбор правил игры, приоритетов и проверку физических AR-привязок на вашей площадке нельзя заменить анализом кода.

## Проверка выполненного выделения

Пройдены 15 автоматических тестов (`npm.cmd test`), браузерное прохождение (`node tests/browser-smoke.cjs`) и производственная сборка (`npm.cmd run build`). Проверены отсутствие обратных импортов платформы в игру, независимые экземпляры runtime с другим контроллером и идентификаторами, адаптация UI, выбор игры и отказ для некорректного имени. Все 23 перенесённых файла ресурсов и их опубликованные копии сверены по SHA-256.

Сборка сохраняет предупреждения о размерах существующих изображений, preview.gif и библиотеки движка. На физических Android/iPhone перенос не проверялся. Существующий CI собирает проект, но автоматический запуск новых тестов в workflow ещё не добавлен. Код не опубликован и не закоммичен в рамках этой задачи.
