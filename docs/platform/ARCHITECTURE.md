# Основа платформы AR-квестов

## Что выделено

Рабочий код разделён на общую основу и первую игру. Pixel Quest использует platform/ через импорты; отдельной копии движка внутри игры нет. Это основа для разработчика, пока не визуальный конструктор и не законченная система плагинов.

```text
platform/
  core/
    game-state.js           состояние маркерного квеста в памяти
    episode-runtime.js      запуск, связь адаптеров, завершение и очистка
  ar/
    register-game.js         регистрация игры и настройка целей 8th Wall
    episode-component.js     адаптер runtime для A-Frame
    marker-manager.js        события обнаружения, обновления и потери
    ar-object-manager.js     создание, привязка, отображение, очистка
  ui/
    quest-ui.js              панели, кнопки и очередь браузерной речи
    quest-ui.css             общий стиль интерфейса квеста
  modules/
    audio/pixel-audio.js     синтез звуков из переданных нот
    analytics/analytics.js   диагностические события и получатель sink

games/pixel-quest/
  app.js                    подключение игры к платформе
  index.html                сцена, камера, внешние библиотеки и ресурсы
  styles.css                оформление демонстрационного режима
  config/
    game.js                 название, фабрики модулей, адаптация интерфейса
    audio-cues.js           мелодии этой игры
  episodes/episode-01/       тексты, переходы и подключение эпизода
  assets/                   модель, изображения и image-targets/
  demo/tap-place.js          исходный демонстрационный режим ?demo=1
  docs/                     сюжет, требования и описание реализации

docs/platform/              архитектура, контракты, анализ и карта переноса
docs/guides/                инструкции для разработчика
```

Папки для ещё не реализованных заданий, инвентаря и сохранений специально не имитируют готовые модули. Полный список пробелов — в [READINESS.md](READINESS.md).

## Направление зависимостей

Игровой app.js вызывает registerARGame. Адаптер A-Frame создаёт createEpisodeRuntime, которому игра передаёт контроллер и фабрику UI. Runtime связывает события маркеров, состояние, объекты и интерфейс. Только контроллер игры принимает сюжетные решения.

platform/ не импортирует games/. AR-адаптеры зависят от A-Frame/8th Wall и браузера; core/ не зависит от DOM. UI пока русскоязычный и рассчитан на системные и персонажные реплики. Набор состояний LOCKED/AVAILABLE/FOUND/COMPLETED и старт с первого маркера — текущий контракт маркерных квестов, не универсальная модель любых игр.

Название Pixel Quest, преобразования подписей кнопок, произношение SYSTEM/UNKNOWN USER и музыкальные мотивы вынесены в config/ игры. UI принимает необязательную фабрику звуков; без неё речь и текст работают без сигналов. Аналитика подключается фабрикой и поддерживает внешний sink, но сама по себе никуда не отправляет данные.

## Сборка и запуск

Из корня репозитория:

```powershell
npm.cmd run serve
npm.cmd run build
npm.cmd run build -- --env game=pixel-quest
npm.cmd test
npm.cmd run test:browser
```

Webpack выбирает games/<id>/app.js и index.html. По умолчанию это pixel-quest. Имя проверяется, отсутствие файлов приводит к понятной ошибке. Одна сборка содержит одну игру и записывается в dist/. Каталога игр и переключения игры внутри страницы пока нет. При публикации другой игры используйте отдельную сборку и адрес; несколько параллельных сборок не должны писать в один dist/.

Сохраняются адреса bundle.js, assets/ и image-targets/ на опубликованном сайте. Источники маркеров находятся в games/<id>/assets/image-targets/, но их JSON imagePath остаётся image-targets/… . Папка external/ и общие инструменты сборки остаются в корне. GitHub Pages workflow продолжает собирать Pixel Quest по умолчанию. Изменения не опубликованы автоматически этой задачей.

## Привязка AR-объектов

Сохранено последнее поведение: объект остаётся после потери маркера, уточняет положение при повторном распознавании и скрывается при завершении эпизода. Это привязка по отдельным маркерам и текущему мировому трекингу. Общей карты, пространственных якорей и сохранения координат между сеансами пока нет. IDEA-001 остаётся предложением.

## Проверка границ

Тесты проверяют прохождение Pixel Quest, звук, независимые экземпляры runtime с другими идентификаторами и отсутствие обратных импортов из platform/ в games/. Браузерный тест использует настоящий A-Frame с имитированными XR-событиями. Он не заменяет распознавание физических маркеров на Android/iPhone и не доказывает универсальность платформы для второй полноценной игры.


## Согласованная библиотека механик: этап 6

Рядом с прежним episode-runtime добавлены event-bus.js, game-clock.js, mechanic-registry.js, mechanic-lifecycle.js и scenario-runner.js в platform/core/. Адаптер platform/ar/mechanic-episode-component.js и platform/ui/mechanic-presenter.js подключают новый сценарий без изменения контроллера episode-01.

platform/modules/mechanics/catalog.js фиксирует 20 стандартных типов; scan.js реализует AR-01, discover.js — AR-02, touch.js — AR-03, collect.js — AR-05, choose.js — AR-06, sequence.js — AR-07; sequence-presenter.js показывает последовательность и подтверждает её окончание; interaction-adapter.js обрабатывает нажатия по объектам; discovery-adapter.js измеряет видимость цели камерой. В games/pixel-quest/episodes/ar-initiation/ отдельно хранятся scenario.js, content.js и component.js. config/game.js регистрирует SCAN, DISCOVER, TOUCH, COLLECT, CHOOSE и SEQUENCE; app.js выбирает onboarding по ?episode=ar-initiation.

В коде реализованы все шесть MVP-механик; остальные типы остаются каталогом. Текущий API и границы: [MECHANICS_RUNTIME.md](MECHANICS_RUNTIME.md). Следующий этап — итоговая физическая приёмка MVP.
