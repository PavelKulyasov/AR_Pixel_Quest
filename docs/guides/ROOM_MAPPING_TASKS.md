# Задачи и подготовка карты помещения для Image Targets

Статус: подготовка прототипа. Общая карта помещения и коррекция по нескольким опорным маркерам пока не реализованы. Чекбоксы отмечаем только после фактического выполнения.

Цель: размещать игровые объекты в заданных местах комнаты и уточнять привязку при обнаружении известных маркеров. Изображения-маркеры не заменяют сканирование стен и геометрии помещения.

## 1. Что подготовить владельцу проекта

### Помещение и маршрут

- [ ] Выбрать одну комнату для первого прототипа.
- [ ] Подготовить план сверху: подойдёт рисунок от руки с размерами комнаты, дверями, стенами и крупной мебелью.
- [ ] Указать единицы измерения; предпочтительно сантиметры или метры, одинаковые на всём плане.
- [ ] Отметить вход, игровые зоны, предполагаемый маршрут и места, где игрок останавливается.
- [ ] Выбрать неподвижную точку отсчёта, например угол комнаты; обозначить два направления вдоль пола. Сложные 3D-координаты самостоятельно рассчитывать не нужно.

### Изображения и печать

- [ ] Подготовить для начала 3–4 разных изображения маркеров на одну комнату. Это стартовый набор для испытания, а не гарантированно достаточное количество.
- [ ] Передать каждое изображение отдельным PNG или JPG в исходном качестве, без перспективных искажений фотографии уже напечатанного листа.
- [ ] Назначить понятные ID и имена файлов: например, room_01_marker_01.png, room_01_marker_02.png.
- [ ] Выбрать различимые, детализированные изображения; окончательную пригодность проверить распознаванием на телефоне.
- [ ] Для первого испытания рассмотреть ширину изображения 20–30 см; окончательный размер определить по условиям комнаты и тестам.
- [ ] Подготовить ровные отпечатки без бликов и закрепить их неподвижно.
- [ ] Измерить фактическую ширину и высоту самого изображения после печати, отдельно от полей листа. Сохранить пропорции оригинала.

### Размещение маркеров

- [ ] Предложить места: один маркер у входа, остальные возле основных игровых зон.
- [ ] На плане подписать ID каждого маркера и расстояния от выбранной точки отсчёта или двух известных стен.
- [ ] Для каждого маркера указать высоту центра изображения от пола, поверхность крепления и направление лицевой стороны.
- [ ] Указать наклон, если маркер расположен не вертикально; для лежащего маркера обозначить направление верхнего края.
- [ ] Сделать обзорные фотографии размещения и отдельные фотографии каждого закреплённого маркера для проверки схемы.
- [ ] Проверить, что при переходах игрок может увидеть опорный маркер или быстро навести на него камеру. Постоянно видеть все маркеры одновременно не требуется.
- [ ] После измерений не перемещать маркеры; если положение изменится, обновить схему и калибровку.

### Игровые объекты

- [ ] Перечислить объекты: терминал, портал, персонаж и другие нужные элементы.
- [ ] Отметить для каждого место на плане, высоту, желаемый размер и направление.
- [ ] Указать, какие объекты неподвижны, а какие могут перемещаться по сценарию.
- [ ] Указать эпизод или шаг появления и исчезновения каждого объекта.

### Условия проверки

- [ ] Записать точную модель Samsung, версию Android и название/версию браузера.
- [ ] Описать обычное освещение комнаты, возможные блики и перекрытие маркеров людьми или мебелью.
- [ ] Указать требуемые расстояния распознавания и максимальную длину маршрута.
- [ ] Согласовать допустимое смещение объекта и время восстановления привязки после возвращения к маркеру; не считать эти показатели уже достигнутыми.

## 3. Задачи разработки платформы — выполняет Codex

Это список будущих работ, а не описание готовой реализации.

- [ ] Проверить изображения и подготовить данные Image Targets для используемого движка.
- [ ] Определить формат карты: ID, единицы, начало координат, позиции и ориентации маркеров, размеры изображений.
- [ ] Отделить общую логику карты в platform/ от конфигурации помещения и ресурсов конкретной игры в games/.
- [ ] Добавить размещение игровых объектов в координатах карты помещения.
- [ ] Реализовать начальную привязку карты по известному маркеру.
- [ ] Реализовать коррекцию общей привязки карты по повторно обнаруженным опорным маркерам с учётом масштаба и ориентации.
- [ ] Добавить проверку устойчивости последовательных наблюдений, обработку выбросов и противоречий между маркерами.
- [ ] Согласовать сглаживание с общей привязкой, чтобы объекты не расходились относительно друг друга при коррекции.
- [ ] Обработать потерю маркеров, возвращение в комнату, паузу приложения и перезапуск эпизода.
- [ ] Добавить понятный статус привязки и подсказку навести камеру на маркер, когда требуется уточнение.
- [ ] Проверить совместимость первого эпизода, AR-инициации и «Побега Нулика».
- [ ] Добавить автоматические проверки преобразований координат и переключения опорных маркеров.
- [ ] Обновить документацию, инструкцию настройки помещения и историю изменений.

## 4. Совместные испытания на телефоне

- [ ] Проверить каждый маркер с расстояний 0,5; 1; 1,5; 2; 3 м, если это позволяет помещение. Это точки измерения, а не обещанная дальность.
- [ ] На каждом расстоянии выполнить пять повторных обнаружений: убрать маркер из кадра, затем снова навести камеру.
- [ ] Отдельно оценить распознавание и устойчивость позиции объекта: успешное обнаружение ещё не гарантирует точную привязку.
- [ ] Проверить неподвижную камеру, медленный поворот, наклон и изменение расстояния.
- [ ] Уйти от первого маркера к другому и проверить отсутствие скачка общей карты.
- [ ] Пройти весь маршрут и вернуться: сверить объекты с выбранными физическими ориентирами.
- [ ] Проверить потерю всех маркеров, перекрытие изображения и повторное обнаружение.
- [ ] Проверить касания объектов и удержание цели в прицеле после коррекции карты.
- [ ] Проверить сворачивание браузера, возвращение в игру и перезапуск эпизода.
- [ ] Записать результаты и при необходимости изменить размеры, количество или расположение маркеров.
