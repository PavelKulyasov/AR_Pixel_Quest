# Инструкции для работы с проектом

## История изменений

После каждого завершённого логического изменения кода, ресурсов, настроек или документации добавляй в конец корневого CHANGELOG.md одну строку на русском языке:

`- ГГГГ-ММ-ДД ЧЧ:ММ:СС +03:00 — краткое описание того, что сделано и зачем (если цель не очевидна).`

Используй фактическое текущее московское время (Europe/Moscow, UTC+03:00). Сохраняй хронологический порядок и предыдущие записи. Связанные правки одной задачи можно объединить в одну запись. Не записывай планы, чтение файлов и консультации без изменений. Не создавай отдельную запись о самом обновлении журнала. Не придумывай результаты проверок; существенные ограничения указывай в записи. Обновляй журнал до финального ответа пользователю.

В каждой записи после описания перечисляй все созданные, изменённые и удалённые файлы с полными путями относительно корня репозитория (например, `platform/ui/quest-ui.js`). Группируй пути по действию: «Созданы: ...; Изменены: ...; Удалены: ...». Пустые группы опускай. Для переименования указывай старый и новый путь. Не заменяй конкретные пути именами папок или масками. Удалённые файлы указывай по прежнему пути. Включай CHANGELOG.md в список изменённых файлов той же записи, без отдельной записи о его пополнении. Обычные результаты сборки и временные файлы не перечисляй, если они не являются самостоятельным результатом задачи. При восстановлении старой истории подтверждай пути по Git или фактически выполненным правкам; не выдумывай неизвестные пути.

## Коммиты

После каждого завершённого логического изменения в репозитории делай коммит с понятным сообщением на русском языке, кратко описывающим, что изменено и зачем (если цель не очевидна). Перед коммитом выполни необходимые проверки и обнови CHANGELOG.md. Включай в коммит только файлы, относящиеся к текущей задаче; не добавляй посторонние изменения пользователя.

## Документация проекта

Перед изменением игровой логики прочитай docs/README.md и следуй указанным там правилам и документации соответствующего эпизода.

После выделения платформы общие документы находятся в docs/platform/, инструкции — в docs/guides/, а канон и требования Pixel Quest — в games/pixel-quest/docs/. platform/ не должен импортировать games/. Новые сюжетные правила и ресурсы размещай в каталоге соответствующей игры.

## Стандарт игровых механик

Для новых механик используй канонические ID AR-01–AR-20 и имена из docs/platform/MECHANICS_CATALOG.md. Отделяй mechanic_id (тип) от конкретного экземпляра шага и от контента. Не создавай отдельные механики для разных сюжетных оболочек одной логики. Приоритет MVP: AR-01 SCAN, AR-02 DISCOVER, AR-03 TOUCH, AR-05 COLLECT, AR-06 CHOOSE, AR-07 SEQUENCE. docs/platform/MECHANICS_MVP_PROPOSAL.md — предложение архитектуры; до явного согласования пользователем не реализовывай механики массово. После согласования внедряй их последовательно с проверкой совместимости первого эпизода. Наличие ID в каталоге не означает реализованный модуль.

Архитектура и правила MVP явно согласованы владельцем 2026-09-27. Продолжай последовательное внедрение без повторного запроса согласования этой архитектуры. Реализованный API и текущий этап смотри в docs/platform/MECHANICS_RUNTIME.md; наличие ID в каталоге по-прежнему не означает готовую реализацию.
